Wire-compatible with 0.34.x: a new client streams from an old host and the other way round, so you can update one side at a time — except on Windows, where the host and its display driver update together.

- **Windows streams with less lag.** The display driver encodes each frame the moment it is composed. Run the installer once; it updates host and driver as a pair.
- **Android decodes PyroWave**, and Android and Apple clients can ask for 10-bit colour on an ordinary SDR screen.
- **A picked game's cover holds until the game is up**, and a settings profile can be bound to one title.
- **Foldable phones split at the hinge**, and you lay out the on-screen controller control by control.
- **A glitch heals without a full refresh** on NVIDIA hosts and on AMD and Intel Linux hosts.
- **Steam Deck: stream a game from Steam's own Play button.**
- **A browser can stream.** Off until you turn it on at the host.
- **Pick where the app opens.** "Start in" chooses the hosts list, the library or a default host's stream.

**A word of caution.** This release rebuilds how every host encodes: Windows encodes inside the display driver, AMD and Intel Linux hosts run a new encoder, and FFmpeg is gone. Changes this large can carry issues we have not found yet. If a stream that was fine on 0.34 misbehaves, tell us, with the host log and the Status page's capture line.

## Before you update

- **Windows: run the installer.** It updates the host and the display driver together; expect a brief black screen while the driver reloads. A 0.34 driver under a 0.35 host refuses to stream and says "driver outdated".
- **Apple and Android: the game-library switch is gone.** Pairing decides whether you see games.
- **Android: clipboard sharing starts off.** Turn it on per host if you want it.
- **Linux, unattended installs:** `--yes` now adds you to the `punktfunk` group on every distro, not only Bazzite and Nobara. Pass `--no-punktfunk-group` to keep the old behaviour.

## New

### Library and launching

- **Launch hold.** The cover flies out of its tile and holds over the stream until the host reports the game running; any press shows the stream early. Launchers never hold.
- **A settings profile per game.** Options on a cover → "Settings profile…". A one-off choice beats the title, the title beats the host, the host beats the defaults.
- **A Desktop tile leads every shelf.** It reads "Resume \<title\>" while the host has a game up, so you can rejoin a game the host started on its own. A host card names that game too.
- **Six more library sources, as plugins.** Ubisoft Connect, Amazon Games and Battle.net on Windows; desktop entries, Flatpak, Bottles and itch.io on Linux; itch.io on Windows too. Install them under Game sources. A Windows launcher that lives in your user profile shows as "not installed" until you run `punktfunk-host plugins grant <dir>` once.
- **Steam Deck: Punktfunk hosts in Steam's "Play from" menu.** The Play button becomes Stream while a host is chosen, and the stream runs as the game, with its art.
- **Linux desktop and Windows clients sort the library the way the console does.**
- **Pick where the app opens.** Settings → "Start in" chooses the hosts list (as before), the library, or straight into a host's stream. With one paired host that host is the default; with more, "Make default host" on a host's Options menu chooses.

### Controls

- **On-screen controller layout editor.** Drag each stick and button, scale it or hide it, on Android, iPhone and iPad. A foldable half-opened on a table puts the picture on the upright half and the controller on the flat one.
- **Quick-action ring on a Mac.** Stream menu, Ctrl+Alt+Shift+O, or Select+A on a pad.
- **Guide and Quick Access on the ring.** Two new slots tap those buttons on the host's controller, so Steam's overlay is a ring press away.
- **Mac: the Steam Controller 2 over USB or a Puck dongle.** Each pad on a Puck reaches the host as its own controller; macOS asks for Input Monitoring once. Windows hosts now present a Puck pad as a Steam Controller 2 instead of an Xbox pad.
- **Windows client: DualSense haptics and pad-speaker rows** in settings, as the Linux client has had.
- **Overlay size is a setting on every client**, and the ring steps it mid-stream. Android TV draws the overlay 1.75× by default; the Apple TV client already did.

### Picture

- **Android decodes PyroWave.** A phone, tablet or TV with Vulkan 1.3 and the compute features the codec needs offers the row; the codec stays opt-in per session.
- **10-bit colour without HDR.** Android and Apple clients can ask for a 10-bit stream on an SDR panel, so gradients stop banding.
- **Windows: any GPU with a Windows H.264 or HEVC encoder can host.** When the vendor's own encoder refuses, the host falls back to Windows' built-in one (8-bit only).
- **Windows: capture health on the Status page.** The session card says healthy, idle, stalled or recovering, and a stalled stream walks a recovery ladder — encoder reset, swap chain, presentation, driver reload — instead of freezing.
- **Headless gamescope hosts get adaptive sync.** Install `punktfunk-gamescope` +pfhdr10 or newer.

### Hosts and installs

- **Two games at once on one Linux host.** On a gamescope-capable box, each client gets its own session — picture, keyboard, pad, audio and mic. Disconnecting one leaves the other running; reconnecting returns to it.
- **A browser can stream (preview).** Turn the host's browser plane on (`--webtransport`); a browser pairs like any other device. Set the allowed pages too, or any page you have open could reach it. The client lives at [punktfunk/client-web](https://github.com/punktfunk/client-web).
- **Linux: the one-liner downloads a setup program.** It asks nothing after the settings screen, installs the client too (`--client`, or a Flatpak where your distro has no package), takes SteamOS through the guided path, trusts the web console's certificate so the browser opens it without a warning, and stops asking the package manager's own "proceed?". Re-running it upgrades a box that already has everything.
- **Windows: Punktfunk's own installer.** Recommended or Custom, the web-console password shown once, the same silent flags as before. The wizard needs Windows 11; a silent install runs anywhere the host does. An ARM64 host installer for Snapdragon X ships on the canary channel — untested on hardware, video only.
- **Omarchy.** The bar widget ships with the host package; its panel has Now, Stats (with sparklines), Displays, Pairing and Devices tabs; every client surface follows the Omarchy theme live; your saved hosts sit in Super+Space; host actions have their own Punktfunk Host menu; the client installs by default.
- **Friends over the internet.** A [guide](https://docs.punktfunk.unom.io/docs/friends-over-the-internet) to letting one friend reach one host without joining your network: Porthole for PC friends, Tailscale sharing for everything else, port forwarding if you run your own router.
- **Network speed test** in the gamepad console's host menu — Android TV, Steam Deck, Linux console, webOS.
- **A screen reader hears the Android console.** TalkBack names the focused row on home, the library and settings.
- **webOS: the controller-optimised UI is a switch**, as on Android.

## Improved

- **Windows: the display driver encodes.** At 4K120 on an RTX 4090 no frame waited more than 6 ms for the encoder, where the old path reached 48. The frame pool keeps the newest frame under load, HDR with 4:4:4 keeps full chroma, and REALTIME GPU priority is the default again.
- **AMD and Intel Linux hosts have their own encoder.** A lost packet heals on the next frame instead of a full keyframe, a bitrate change lands in place, and HEVC 10-bit carries its HDR10 metadata. A mirrored monitor now encodes at the client's size, so a 4K screen to a Deck is not a 4K stream.
- **The packages carry no FFmpeg.** Fedora needs no RPM Fusion, the Windows installer is smaller, NixOS loads Vulkan and VAAPI again, and a SteamOS host builds four minutes faster (delete `target-steamos/ffmpeg` to reclaim the space).
- **A glitch heals without a full refresh.** NVIDIA hosts everywhere and AMD/Intel Linux hosts repair the picture row by row, without the bitrate spike an IDR costs. Windows NVIDIA hosts also stop forcing a full keyframe on every lost frame, and Apple clients accept the repaired frame instead of asking for one — a ~250 ms hitch per loss on Wi-Fi, gone.
- **Linux desktops keep the refresh rate they run at.** Hyprland is captured directly (165 fps at 165 Hz where the portal gave 82), GNOME 49+ paints a frame when the stream asks for one, and KDE follows its own refresh signal and tears no more under load.
- **Audio on a bursty link.** A Wi-Fi link that delivers audio in clumps no longer has each clump trimmed and concealed; and the loss-protection floor is now 5 %, so a two-packet burst on a clean link costs no frame.
- **The bitrate stays where your decoder has headroom.** A phone decoding near its frame budget used to be pushed to the link's ceiling anyway, so every hiccup became a stall; the rate now parks there, or steps back one notch, and climbs again only once the decoder has room.
- **Trackpad scrolling matches your fingers**, on Windows, Linux and Mac clients and on every host; it used to run about five times too far.
- **A sleeping host shows Offline, and auto-wake fires for it**, on every client. A stale advert no longer reads as a live host.
- **Apple TV presents video through the system renderer** on tvOS 17.4 and newer, dropping a two-refresh delay. Menu backs out of every screen, and the Siri Remote drives the ring.
- **The quick-action dial follows the left stick** on Apple and Android, as on the desktop.
- **Every connected controller drives the desktop launcher**, not only the newest, and a Deck in Game Mode forwards every pad Steam Input wraps.
- **The console's refresh row keeps 144, 165 and 240 Hz**, and a resolution or rate one client cannot list survives opening Settings there.
- **Windows: a standby TV that keeps re-lighting itself is parked for the session** instead of costing a rebuild each time.
- **A pinned data port works behind NAT**: the host answers where the hole-punch came from.
- **Windows client crashes name the faulting module** in `client.log`, and the client ships its own VC++ runtime, so an old redistributable no longer crashes it on the first text.

## Fixed

- **Android:** Select+A opens the ring on any pad. Resetting a profile's 10-bit row sticks. "Low-latency mode" off now keeps the same decoder with its boosts off, so "Prefer smoothness" works in both states; if you turned it off for a device that misbehaved, try it on again. A Steam Controller 2 over Bluetooth now behaves as a controller instead of a mouse and keyboard, rumbles and reports gyro, and comes back after powering off. Hosts appear reliably: the app runs one discovery browse instead of two that split each other's answers.
- **iPad and Apple TV:** audio no longer sits 40–90 ms behind the picture with the mic off, and the mic path no longer drops out every half minute.
- **Mac:** a Mac with no microphone connects instead of crashing. The desktop mouse stops at the window edge. ⌘ chords pass through under the desktop mouse model. A wrong PIN says so instead of a status code.
- **Apple TV:** the Siri Remote pointer no longer jumps toward wherever the surface is touched.
- **Windows host:** RX 400/500 and Vega GPUs encode again. NVENC no longer pins a stream at 10 Mbps. A game's own display mode survives the host re-asserting its displays. A launched game starts in its own folder (Ryujinx runs). The forwarded cursor is no longer three times too large from a 300 % desktop. The sign-in, lock and UAC screens show in the stream instead of a frozen frame. A pointer gesture no longer rests one step behind. A resize on an idle desktop no longer ends the session. A host update whose download got stuck retries whole instead of failing on every attempt. An I-beam over a text box no longer draws as a grey block, and a moving mouse on a 240 Hz desktop no longer sends the client more frames than its decoder was sized for.
- **Windows client:** the picture below the first tile row is no longer green on AMD GPUs with 4K120 AV1.
- **Linux host:** a GNOME 50 host survives a mid-stream resize. An odd-width window from an Intel host is no longer sheared. A KDE session's streamed display sits at the desktop origin, so popups land on screen. AMD and Intel hosts offer AV1 again. A capture-loss rebuild replaces the stalled display instead of adding one.
- **Steam Deck host:** a dedicated game session runs on its own gamescope, so a second launch no longer kills the stream seconds before it starts, and a Moonlight client switching Desktop to Game keeps its seat. A SteamOS host updates again after the preview channel moved FFmpeg ahead, and a rebuild that failed no longer runs for 25 minutes on every boot.
- **Every client:** a damaged frame is held instead of shown, so the grey smear that lasted until a scene change is gone, and Intel Arc, Linux iGPU and older Windows GPU clients check before lifting a freeze. A scaled Wayland desktop no longer draws the forwarded pointer 2.25× too large. A game launched from the library no longer opens soft and stuttering: frames arriving while the cover still held were read as a backlog and cut the bitrate to a quarter before the first one was shown.
- **Hosts and pairing:** one client stalling its handshake no longer blocks every other client's connect for up to 8 s. Forgetting one unpaired host no longer forgets them all; Windows Forget removes the host you picked. A pairing that failed to save says so instead of "Paired". Request access connects instead of cancelling itself. A host-side setup failure — no encoder, no display driver — reads as one on iPhone and Android.
- **Desktop client:** capturing a quick-action chord no longer kills the app, closing the window no longer ends a live stream, an open dial no longer strands a button down on the host, duplicating a profile copies what is on screen, clearing the controller pin clears it, and a slow library fetch no longer overwrites the host you asked for last.
- **Controllers:** two pads no longer swap rumble or raw reports, a DualSense's haptics and speaker come from its own pad, and its adaptive triggers fire in game.
- **Installer:** a fresh Linux box gets a running web console, a box with no desktop is set up for gamescope, and Omarchy's desktop entries open every surface in app mode. NixOS's `punktfunk-gamescope` ships the reaper it starts games through, so a session no longer comes up empty.

## Security

- **Android: clipboard sharing starts off.** Turn it on per host if you want it.
- **A fake advert on the LAN can no longer replace a saved host's wake address**, and a machine that inherited a sleeping host's IP no longer passes as that host.
- **Windows: a secret planted before the host's first run is not adopted.** A token, key or web-console password another local account left in the host's data directory is set aside; the installer rotates the password. Elevated helpers and the AMD driver library are loaded by absolute path. A plugin can no longer have the host end a process outside the streamed session, and a token set in `host.env` no longer reaches games and hooks.
- **Deleting a Moonlight device's access record ends its session** instead of lifting every restriction on it.
- **`punktfunk-client --library` verifies the host again**; an unpinned host is refused unless you pass `--fp`.
- **A pairing PIN stays out of the process list** on Linux.
- **Browser plane:** loopback-only routes are never answered cross-origin, and `serve --open` refuses to start with the plane on and no allowed pages.
- **A corrupt or hostile stream cannot crash the client**: a reserved AV1 bit is a parse error, not an abort, and a host's audio settings are bounded before they size a buffer.
- **A GameStream pairing ceremony belongs to one peer**; another host cannot hijack a client's PIN exchange. A LAN peer holding connections open can no longer exhaust the host's Moonlight or management listeners.
- **Windows: a link another account planted in the host's data directory is refused** instead of hardened in place.
- **Local hardening:** a plugin's freed launch port can no longer be squatted by another process, the web console verifies the host's own identity on its loopback hop, a seat display answers only its own session, and a browser's sign-in challenges are budgeted per address.
